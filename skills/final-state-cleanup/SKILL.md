# Final State Cleanup

将当前工作区和分支整理成可交付、可维护、可复核的最终状态：保留最终实现及其必要依赖、测试和文档，合并有价值的结论，删除已经失去用途的中间过程。直接完成有依据且在授权范围内的清理；只有具体内容的归属、最终版本或删除损失无法判断时，才用简短文本澄清，并继续处理其他独立项。

## 自动触发时机

处理 Issue 或 PR 的实现任务时，把此 Skill 作为默认收尾步骤：最终方案已形成后、最终验证和交付答复之前自动执行，无需用户再说“清理一下”。即使执行过测试或 Review，也要检查清理是否改变其验证对象，重跑受影响的验证。若随后又修改实现，再检查这次修改是否留下新的过程残留，然后完成必要重验；无新变化时不重复完整清理。

这里的完成指本次实现准备交付，不以关闭 Issue 或合并 PR 为触发条件，也不授权这些外部动作。用户要求只读调查、纯 Review、仅出方案或明确保留过程材料时，遵守该边界；尚未完成的功能不能以“清理”为名删除。显式调用时可以直接整理用户指定的现有工作区或分支。

## 确定范围与最终状态

先读取项目规则和当前任务上下文，确认最终要交付的功能、文件及文档位置。默认只清理当前任务在当前工作区和分支留下的内容；清理整个仓库、其他 worktree 或嵌套仓库需要有对应范围的授权。不要因为处在收尾阶段就把尚未完成的功能当成废弃过程。

在任何修改前核对真实路径、Git 根目录、分支、HEAD、worktree、暂存与未暂存改动、未跟踪文件及相关忽略目录；按需读取分支相对基线的 diff。基线优先使用用户指定或当前任务已经确认的引用，再考虑已知的分支来源；不要猜测 `main` 就是基线，也不要把 upstream 的同步差异当作整个功能分支的改动。缺少可靠基线时，说明只能完成当前工作区范围的收敛。

识别本次任务与并行工作的归属，记录拟修改内容的初始状态；共享文件精确到 hunk。修改前重读目标，发现并发改动就重新判断，无法分离时保留冲突项。不得覆盖其他人的 WIP、替别人结束任务，或通过清理把未提交成果丢弃。

## 判断保留、整合和删除

按内容、依赖与当前用途判断，文件名、修改时间、是否跟踪或是否被忽略都不能单独证明可删。

| 处理 | 判断依据 |
| --- | --- |
| 保留 | 最终实现、必要资源和配置、依赖清单与锁文件、仍需使用的迁移或运维脚本、有效测试与 fixture、构建发布所需文件、最终使用或维护文档，以及项目要求保留的决策、许可、变更和验收证据。 |
| 整合后删除 | 阶段总结、交接草稿、调查笔记、重复说明中的有效结论已经进入现有权威文档；原文没有独有约束、未决事项或仍需保留的证据。 |
| 删除 | 已被最终实现替代且无调用方的试验代码、无用途的调试输出和临时开关、一次性复现脚本及其废弃输出、重复产物、过时计划与过程报告、已确认无用途的临时截图和日志。 |
| 暂时保留 | 归属或用途不清、仍有引用或外部消费者、包含独有信息、尚未闭合的任务记录、恢复材料、其他活跃工作或无法验证安全性的内容。报告具体原因，继续清理已确认的项。 |

最终产物不只包括可执行文件，也包括维护和验证最终行为需要的源码、测试、配置及文档。不要为减少文件数删掉回归测试、必要解释或尚未执行的迁移；不要把锁文件、`.env`、本地数据、用户附件、`AGENTS.md`、`CLAUDE.md`、活跃任务台账或 `.codegraph/` 当成默认垃圾。

## 执行收敛

先用一句话说明交付目标和已确认的清理范围，然后执行，不为已授权且有依据的普通清理反复请求确认。

优先更新项目已有的权威文档，使其准确反映最终行为、使用方式、必要设计决策、限制和实际验证结果；把过程材料中的有效结论及未决事项转移进去，去掉过时描述并修复引用，再删除重复或失效材料。没有合适位置时才创建必要的最终文档。不要为了记录清理本身再生成日报、清理台账、归档副本或第二套交接文档；用户或项目明确要求审计记录时遵循其约定。

主动检查最终实现及相对基线的完整任务 diff，寻找探索阶段遗留的重复逻辑、被替代的调用路径、无消费者的抽象和参数、一次性调试开关、临时 fallback、无效配置以及与最终方案不一致的注释，不限于清理已经列出的临时文件。逐项确认用途与行为，不能因“看起来多余”就删除真实兼容、容错或边界处理。

删除废弃实现前检查调用、导出、配置、测试、脚本及文档引用；存在 `.codegraph/` 且 CodeGraph 可用时优先用它分析依赖，再用 `rg` 补充。删除本任务遗留的死代码和过时兼容路径，保留最终方案确实需要的行为，避免借清理发起无关重构或格式化。只在消费者已迁移且行为保持成立时，才移除看似过渡性的代码。

精确处理已确认路径或 hunk。删除目录前检查真实路径、符号链接、嵌套仓库、跟踪内容和占用情况，不沿链接删除范围外目标，不误伤活跃构建或进程。构建缓存和依赖目录只有确属本次清理范围且不再需要时才删除，不能把交付收尾自动扩大成磁盘清理。若确需恢复副本，放在工作区外并说明位置和保留原因，不能把所有过程材料搬进仓库的 `archive/` 就声称收敛完成。

## Git 与交付边界

“收敛分支”默认指整理相对基线的最终 diff 和工作区内容，不代表压缩或改写提交历史。保持当前 checkout、HEAD 和已有暂存内容的归属，不自动提交、推送、rebase、squash、amend、reset、stash、切换分支或删除引用；这些动作需要已有的明确授权。禁止 Merge PR。

不使用 `git clean`、`git reset --hard`、批量 `git restore`、`git add -A` 或笼统递归删除来制造“干净”结果；有价值的最终修改可以保持未提交，工作树无改动不是完成标准。

保留当前分支、工作区和交付载体；删除分支、worktree、独有提交或恢复材料属于另外的明确授权范围，远端引用与外部服务不在默认清理范围。

## 验证与交接

清理后检查最终 diff、暂存与未暂存改动、未跟踪残留及文档引用，确认每项删除都有依据、保留产物完整、其他工作未被覆盖；Git 仓库执行 `git diff --check`，有暂存改动时也检查 `git diff --cached --check`。可靠基线存在时一并审视分支提交和当前改动形成的最终内容。

按实际变更运行必要且针对性的验证：删除代码或资源时验证受影响行为，调整文档时检查内容和链接；项目强制门槛仍须执行。检查生成的临时产物需要再次按同样边界清理，不能删掉仍需保留的验收证据。发现问题先修正并重验，不用旧测试结果冒充清理后验证。

最终答复简要说明保留的最终产物与文档位置、删除或整合的主要内容、实际完成的验证，以及具体未清理项和原因；若使用了恢复副本，说明位置。区分源码、本地测试、远端 CI、部署及业务验收，未执行的层次不声称通过。只在授权范围内的确认项已经完成、最终产物可用且剩余项明确时报告本次清理完成；仍有阻塞时直接说明。
