# Approve another author’s passing PR

For an explicitly targeted GitHub PR authored by someone other than the authenticated `gh` user, a `review`, `review deep`, `review auto`, or `re-review` invocation authorizes the coordinator to submit a formal **Approve** review automatically when the selected mode passes. Do not ask for confirmation again. This applies to any unambiguously resolved PR locator, including a URL or repository-qualified number; it does not expand the mode's separate ordinary-comment authorization. Honor an explicit instruction to keep results local or not approve. Never approve the authenticated user's own PR or an inferred PR behind a local branch review.

Passing means `Review-ready` for ordinary/auto review, the validated clean gate for deep review, or `All resolved` for re-review. Required findings, unresolved material questions, and incomplete coverage block approval; optional suggestions do not. Re-review approval retains its stated acceptance scope and must not claim a new broad review. Reviewers remain read-only; only the coordinator submits the formal review.

Immediately before approval, use authenticated `gh` to verify the PR is open, resolve both author and current account, and compare the live head OID with the reviewed OID. If the head changed, do not approve the newer revision: auto starts another cycle; one-shot modes report that approval was skipped because new commits need review. This check guards approval only and does not change existing comment-delivery rules. Submit `APPROVE` through `gh api` with `commit_id` explicitly set to the reviewed OID and a concise evidence-bounded review body. Reuse an existing effective approval by the same account for that head instead of duplicating it. Read back the formal review and verify its author, `APPROVED` state, and commit ID before reporting approval, with its URL. If submission has an uncertain outcome, inspect existing reviews before retrying; if permissions or verification fail, retain the local verdict and report approval as incomplete. Never treat a local clean verdict or an ordinary issue comment as an actual GitHub approval. Never merge a PR.
