# Tidy mode

## 核心逻辑

先确认授权范围和最终交付位置，再判断内容的当前用途及文件独立保留的必要性；保留最终实现、必要依赖、测试和使用维护文档，将过程材料的有效结论、未决事项及证据入口归入现有权威位置，删除确认失效或整合完毕的内容；最后检查 diff、引用和受影响验证。完成标准是冗余已清除、信息有归属、交付物可用、剩余项明确。

## 正向限定式（Inclusion / Allowlist）

- **调用与范围**：仅在显式选择 `<cyh-flow> tidy ...` 时执行；按用户指定范围处理，未指定时限于当前任务在当前工作区和分支留下的内容。清理整仓、其他 worktree 或嵌套仓库，仅在已有对应范围授权时执行；显式组合模式时保持用户顺序及各阶段权限。
- **代码检查**：仅当范围包含代码整理时，审视相关最终实现及相对可靠基线的完整任务 diff，检查调用、导出、配置、测试和文档中的消费者，再删除已被替代的实现、死代码或过渡路径。文档清理只核查相关文档、直接引用及必要证据；发现范围外代码问题时说明，扩大清理须有对应授权。
- **独立文档**：仅当材料有明确的长期使用、维护或审计用途时，保留为独立文档；内容有价值或存在可修复的引用，不能单独证明原文件必须保留。任务总结、测速汇总及 PR 验证报告应先判断能否并入已有权威位置；仅在长期信息确需保留且没有合适位置时新建最终文档。
- **并行分析**：仅当依赖或引用核查可独立开展，且收益超过协调成本时，委派只读 sub-Agent；普通清理由协调者直接完成，始终只有一个清理写者。
- **目录与缓存**：仅当内容属于清理范围、已确认无用途，且真实路径、符号链接、嵌套仓库、跟踪内容和进程占用均已检查时删除；不得沿链接删除范围外目标。确需恢复副本时放在工作区外，并说明位置及原因。
- **Git 与外部动作**：仅在已有明确授权时执行 commit、push、PR 编辑、rebase、squash、amend、reset、stash、切换或删除分支、worktree 及引用；tidy 本身不授予这些权限。任何方式的 Merge PR 均禁止。

## 负向排除式（Exclusion / Denylist）

- **清理对象**：范围内已确认失效的试验实现、调试输出、临时开关、脚本及重复过程材料默认清除；排除仍有消费者的内容、尚未迁移的独有信息或必要证据、有效测试与 fixture、待执行迁移、活跃任务及恢复材料。文件名、时间、跟踪或忽略状态都不能单独证明可删；锁文件、`.env`、本地数据、用户附件、项目规则和 `.codegraph/` 不作为默认垃圾。
- **工作区改动**：默认只精确修改已确认归属的路径或 hunk，排除其他人的 WIP、未完成的功能及无关重构或格式化。修改前核对真实路径、Git 根目录、分支、HEAD、worktree、暂存、未暂存、未跟踪及相关忽略内容，并重读目标；不得用 `git clean`、`git reset --hard`、批量 `git restore`、`git add -A` 或笼统递归删除制造“干净”结果。
- **验证与交接**：默认只做实际改动影响的检查，排除无关环境体检、无依据的全量回归和无变化时的重复核查。文档检查内容、链接及搬运或修改的事实和数字；代码或资源检查受影响行为。执行 `git diff --check`，有暂存改动时再执行 `git diff --cached --check`；最终简述整理结果、实际验证、未清理项及原因，不另建清理报告、台账或归档副本。

## 特殊例外式（Exception / Override）

- **保留要求覆盖默认清除**：若用户或项目明确要求独立保留原文、决策、许可、变更、验收证据或审计记录，则按该要求保留；只读调查、纯 Review 或仅出方案的请求不执行清理修改。
- **不确定性覆盖立即处理**：若归属、用途、最终版本或删除损失无法确认，或目标出现无法分离的并发改动，则暂留该项并继续独立项；只有必要信息仍无法确定时用简短文本澄清。若缺少可靠分支基线，只处理当前工作区可确认的内容；不猜测 `main`，也不把 upstream 同步差异当作完整任务 diff。
- **强制门槛覆盖最小验证**：若用户或项目要求特定检查，则执行该门槛。清理后变更了代码、资源或验证对象，重跑受影响检查；无新变化时复用仍适用的事实与回执。按实际涉及的源码、本地测试、CI、部署及业务验收分别报告，不以旧版本或其他层次的证据冒充本次验证。
